## Obsidian application tracker (Dataview)
`Applications/` holds one markdown note per program with frontmatter Dataview can query. `MY APPLICATIONS.md` is the dashboard (needs the **Dataview** community plugin installed + enabled). Edit each program note's `applied` / `stage` (`to-apply`→`applied`→`OA`→`interview`→`offer`/`rejected`) / `referral` and write under *My notes*. `gen-notes.js` (run by `/refresh-tracker`) refreshes the data fields but **preserves your personal fields + body** (matched by the `key` field). This personal tracker is separate from the website's localStorage Applied checkbox.

## Data schema (per internship)
`company, program, category, class_years (["2028"]/["2029"]), location, status (open|program-page|closed|none|unknown), apply_url, notes, acceptance_rate, competitiveness` — open ones also: `posted_date, close_date`.
Empty `class_years` = hidden from both toggles (MBA-only / no program).

## How to update the data (full refresh)
Use the **/refresh-tracker** skill, or do it manually:
1. Read `data/roster.json` + `Map/Subagents/*` for the company splits.
2. Spawn **Sonnet** research subagents per subagent group. ⚠️ Tell each: *"Do ALL work yourself; do NOT spawn sub-agents"* (agents 3C/3D stalled last time by delegating).
3. Compile results into `data/agentN_results.json` + `data/sophomore_results.json`.
4. `node add-estimates.js`
5. **Re-verify every `open` with Opus** (see lesson below) → `fix-status.js`-style corrections; add posting dates via `add-postdates.js`.
6. `node build-data.js && wrangler deploy`
7. Verify: `curl https://internship-tracker.jz-tracker.workers.dev/api/data`
8. Update Obsidian: Dashboard.md + agent notes "Open now" + Run Log date.

## Hard-won lessons (DO NOT repeat these)
1. **`open` ≠ page loads.** An HTTP 200 on a careers/program page does NOT mean the application is accepting. Only mark `open` with positive evidence (live req + active Apply, window covering today, or future close date). Bot-walled/unconfirmable → `program-page`, never `open`. Verify with **Opus**. (This was the JPMorgan Fellowship bug — 26 of 36 "open" were wrong.)
2. **KV writes fail under the OAuth token** (`Authentication error 10000`). Data is **bundled into the Worker** (`build-data.js` → `src/data.json`), not pushed to KV. The Worker only trusts KV if it has `.agents`; otherwise serves the bundle.
3. **Don't let the cron write KV** — it would clobber the served data. The `scheduled()` handler is a no-op heartbeat.
4. **wrangler 4.x syntax:** `wrangler kv namespace create` / `wrangler kv key put` (space, not `:`).
5. **Bot-walls ≠ broken** (Workday/Oracle/Greenhouse/Eightfold return 403/empty to fetchers but load in a browser) — mark `bot-walled` in notes, keep the link.
6. **Class-year shift:** "2027-grad" postings = current rising seniors; the next cycle (opens Aug–Nov 2026) targets Class of 2028. Tag forward-looking.
7. **Portfolio-company traps:** `jobs.sequoiacap.com`, `futureleaders.silverlake.com`, `jobs.a16z.com`, `jobs.lsvp.com` are portfolio jobs, NOT the fund's own roles.

## Features on the site
- Three tabs: **By Agent**, **🎓 Sophomore Internships**, and **🆕 What's changed**.
- **🆕 What's changed** = the changelog. `build-data.js` auto-diffs each refresh (status flips, programs added/removed) → `data/changelog.json` → bundled into the Worker. Newest entry first; updates automatically on every refresh.
- Class of 2028 / 2029 toggle; status + role filters; search.
- Each card: status pill · est. acceptance rate + competitiveness · (open only) posting/close dates · apply link.
- **Applied checkbox** — saved in the browser's localStorage (key `applied::<company>::<program>`), survives every redeploy. Stats bar shows applied count; "Hide applied" filter available. ⚠️ Because keys are `company::program`, keep those two fields stable across refreshes or checkmarks won't carry over.
