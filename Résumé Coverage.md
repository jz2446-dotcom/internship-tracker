## ✅ Résumé coverage (all open roles)
Every OPEN role and whether it has a résumé. `resume = true` + a `resume_url` means covered.
```dataview
TABLE WITHOUT ID
  company AS Company,
  file.link AS Program,
  choice(resume, "✅ have", "⚠️ NEEDS ONE") AS "Résumé",
  choice(resume_url, resume_url, "—") AS "Download (/resume/<id>)",
  category AS Keywords/Focus
FROM "Internship Tracker/Applications"
WHERE status = "open"
SORT resume ASC, company ASC
```

## ⚠️ Open roles still missing a résumé
If this table is **empty, coverage is complete** (all open roles have a résumé). Any row here is an open role the [[Résumé Agent]] still needs to generate.
```dataview
TABLE WITHOUT ID company AS Company, file.link AS Program, deadline AS Closes
FROM "Internship Tracker/Applications"
WHERE status = "open" AND (resume != true OR !resume_url)
SORT deadline ASC
```

## 📊 Coverage count
```dataview
TABLE WITHOUT ID
  choice(resume, "✅ résumé generated", "⚠️ needs résumé") AS Coverage,
  length(rows) AS Count
FROM "Internship Tracker/Applications"
WHERE status = "open"
GROUP BY choice(resume, "✅ résumé generated", "⚠️ needs résumé")
SORT key DESC
```

## How this stays current
- The `resume` / `resume_url` frontmatter fields are set on the open-role notes in `Applications/` (25 agent/soph cards + 2 🍂 fall cards this run).
- When the tracker refreshes and a new role opens, add `resume: true` + `resume_url: "/resume/<id>"` to its note once the [[Résumé Agent]] has generated its résumé — it then appears here automatically, and the "needs one" table flags any open role that doesn't yet.
- **Efficiency:** this board is the at-a-glance answer to *"which open roles still need a résumé?"* — no re-deriving from the JSON or the site each time.

*Data source: `data/agent*_results.json` + `data/sophomore_results.json` (open entries carry `resume_url`), mirrored into `Applications/` frontmatter. See [[Résumé Agent]] · [[Internship Tracker MOC]] · [[Run Log & Lessons]].*
